# 演示视频录制与答辩介绍指南

## 1. 演示视频建议结构

建议录制 5 到 8 分钟，按下面顺序讲：

1. 项目背景：自己做 Web 开发或 AI Demo 后，需要知道 Linux 服务器上的服务是否稳定运行。
2. 展示公网博客：浏览器打开 `http://115.29.184.235/`，说明这是部署在云服务器上的个人技术博客。
3. 登录服务器：SSH 登录 CentOS 服务器，进入 `/opt/ops-assist-project`。
4. 查看博客服务：执行 `systemctl status ops-blog --no-pager`。
5. 查看端口：执行 `ss -tlnp | grep ':80'`。
6. 健康检查：执行 `curl http://127.0.0.1/healthz.txt`，解释返回 `ok` 表示服务器本机服务可访问。
7. 完整巡检：执行 `./ops-assist all`。
8. 展示报告：打开或输出 `reports/report_*.md`，重点展示“巡检项目说明表”。
9. 总结：说明项目把部署、巡检、日志诊断、报告生成串成了完整闭环。

## 2. Windows 录屏方法

推荐使用 OBS Studio，免费且稳定。

步骤：

1. 下载并安装 OBS Studio。
2. 打开 OBS，添加“显示器采集”或“窗口采集”。
3. 添加音频输入设备，选择电脑麦克风。
4. 设置录制格式为 MP4 或 MKV。
5. 开始录制前，把浏览器、PowerShell、项目报告窗口都准备好。
6. 点击“开始录制”，按演示结构操作。
7. 录完后点击“停止录制”，检查声音和画面是否清楚。

如果不想安装软件，可以用 Windows 自带 Xbox Game Bar：

```text
Win + G
```

然后点击录制按钮。但 Xbox Game Bar 对桌面和部分窗口支持不如 OBS 稳定。

## 5. 答辩介绍提纲

### 项目背景

- 个人 Web 项目或 AI Demo 部署后，需要确认服务器稳定运行。
- 手动执行命令容易遗漏，例如只看网页能打开，却不知道磁盘、内存、日志和服务状态。
- 因此设计一个命令行巡检助手，把常见运维检查自动化。

### 系统功能

- 系统资源巡检：CPU、内存、磁盘、进程。
- 服务与端口巡检：检查 `ops-blog`、`sshd`、80、22 等。
- Web 健康检查：访问 `/healthz.txt`。
- 日志异常分析：扫描错误、失败、拒绝访问、超时等关键词。
- 智能诊断建议：把异常转换成处理建议。
- 报告生成：输出 Markdown/HTML 报告。
- 博客部署：提供真实 Web 服务作为巡检对象。

### 技术实现

- Bash：适合 Linux 系统管理，负责主流程、系统命令调用、服务部署。
- Python：负责诊断建议和报告生成，便于文本解析和结构化输出。
- systemd：管理博客服务，实现开机自启和状态查看。
- Git/GitHub：保存代码、文档和提交记录。

### 项目亮点

- 有真实公网部署，不只是本地模拟。
- 有完整闭环：开发博客 -> 部署到 Linux -> 巡检 -> 日志诊断 -> 生成报告。
- 巡检报告能解释每个检查项，便于非运维人员理解结果。
- 配置化程度较高，别人可以修改服务、端口、健康检查地址后用于自己的服务器。

## 6. 常见答辩问题回答

问题：为什么健康检查只返回 ok？

回答：健康检查接口主要给程序判断服务是否可用，不是给用户阅读。返回 `ok` 简洁、稳定、容易判断。用户真正访问的是博客首页，巡检脚本访问健康接口确认服务状态。

问题：为什么用 127.0.0.1？

回答：因为巡检脚本运行在服务器上，127.0.0.1 代表服务器自己。这样可以先确认服务本机是否正常。如果本机正常但公网打不开，就可以把问题定位到安全组、防火墙或公网网络。

问题：别人能不能用？

回答：可以。别人可以从 GitHub 克隆项目，在自己的 Linux 服务器上修改配置文件中的服务名、端口和健康检查地址，然后运行 `./ops-assist all`。

问题：项目和 Linux 课程有什么关系？

回答：项目使用了 Linux 常见系统管理命令、Shell 脚本、systemd 服务管理、日志分析、端口检查、权限和部署流程，符合 Linux 系统管理与 Shell 编程课程内容。
