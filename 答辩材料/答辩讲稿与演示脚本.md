# 答辩讲稿与演示脚本

## 6 分钟答辩节奏

### 1. 项目介绍（约 50 秒）

我的项目是 Linux 运维智能巡检与日志诊断助手，主要服务课程实验机、WSL/Ubuntu 测试环境和小型 Web 主机。日常排查时需要反复执行 df、free、ps、ss、systemctl、grep 等命令，信息分散，也不方便保存。本项目把这些命令串联为一键巡检流程，自动生成诊断建议和 Markdown 报告。

### 2. 需求与设计（约 70 秒）

系统分为五个模块：主入口 ops-assist、系统巡检模块、日志分析模块、诊断建议模块、报告生成模块。输入是配置文件和日志文件，处理中使用 Bash、Linux 命令、grep/sed/awk、Python，输出是 logs 中间结果和 reports 报告。

### 3. 现场演示（约 2 分钟）

```bash
cd /d/linux开发
export LANG=C.UTF-8 LC_ALL=C.UTF-8 PYTHONIOENCODING=utf-8
./ops-assist help
./ops-assist all
ls reports
head -80 reports/report_*.md
```

演示时重点说：

- check 采集系统信息、磁盘、进程、端口、服务。
- log 使用样例日志统计 failed、denied、timeout、OOM 等异常。
- diagnose 根据规则输出排查建议。
- report 汇总生成 Markdown 报告。

### 4. 测试和 Git 记录（约 1 分钟）

```bash
bash tests/test_workflow.sh
git log --oneline -8
```

说明 11 项测试全部通过。Git 记录从 v0.1 到 v1.0，再到答辩前两次真实修复，体现了开发和调试过程。

### 5. 总结（约 40 秒）

项目体现了 Bash 脚本、Linux 系统命令、grep/sed/awk、管道重定向、crontab、Python 和 Git。后续可改进为邮件/企业微信告警、趋势图和 Web 可视化。

## 老师可能提问

1. 为什么不是大型平台？
   - 课程重点是 Linux 系统管理和 Shell 编程，所以项目聚焦可验证的命令行自动化。
2. 没有 sudo 怎么演示日志？
   - 项目提供 samples/sample_logs/syslog_sample.log，可在普通用户环境演示。
3. AI 用在哪里？
   - 用于辅助梳理测试思路、分析报错和优化脚本结构；最终以本地运行和 Git 提交验证为准。
4. Git 提交怎么说明？
   - 说明每个版本对应一个模块或一次修复。不要声称不存在的个人提交。
